# 源码基线审计（2026-11-16）

## 范围与环境

审计对象为用户提供的 `addressbook.zip` 解压源码。原工作区根仓库实际是 StudySeat；为避免混淆，通讯录放入独立的 `renjian-addressbook/` Git 仓库。压缩包内没有 Git 历史、锁文件、第三方依赖清单、根目录 `AGENTS.md` 或 `CODEX_MASTER_PROMPT.md`。后两份按用户提供的项目约束补入本项目根目录。Python 3.13.15 可用；项目要求 Python 3.10+，只用标准库。前端为原生 HTML/CSS/JavaScript，由 `ThreadingHTTPServer` 提供服务。

## 已有功能与数据

- `app.py`：本地 HTTP API、`data/contacts.json` JSON 持久化、创建/编辑/删除、姓名校验、搜索/星标筛选、`.xlsx` 读写。
- 联系人模型：姓名、电话列表、邮箱列表、公司、地址、备注、favorite、id。新增/编辑后数据写临时文件并 `os.replace`。
- 前端：单页联系人列表、搜索、统计、星标切换、原生 `<dialog>` 新建/编辑、确认删除、文件选择导入、Excel 下载。
- Excel 当前固定 7 列；联系人一行，但多电话/邮箱以换行形式收在单格。导入追加、不去重，整批解析和校验后再写入。
- 联系方式无标签字段，无社交方式。当前界面主要说明多电话/邮箱，但不可区分手机号/工作电话等标签。
- 数据仅绑定 `127.0.0.1`，未上传远端服务；当前浏览器页面的可见版本和 ZIP 源码并非同一运行环境。

## 基线验证

执行：`python3 -m unittest discover -s tests -v`

结果：3 项通过，0 项失败。当前测试覆盖 CRUD/星标筛选/搜索/姓名必填和一个多电话 Excel 往返样例；缺少 HTTP 接口、导入异常/重复策略、公式注入、多个联系人、每个信息项独立列、持久化重载、键盘/响应式/无障碍及性能测试。没有配置独立 build 或 lint 命令。

## 已知问题与风险

1. **Excel 评分风险**：多个电话/邮箱合并到一个单元格，未达到“每种信息项分别列”的作业要求。需要扩展为动态独立列，同时兼容旧版 7 列模板和当前换行格式。
2. **数据模型限制**：无联系方式标签和社交方式。扩展时需向后兼容现有 JSON；不得清空或重置现有数据。
3. **导入安全**：解析整批后统一写入是非破坏性策略；没有去重逻辑，当前 README 已说明重复会追加。需覆盖坏 ZIP/XML、坏表头、缺少 sheet、重复行和超大文件边界。
4. **导出安全**：当前导出使用 inline string，降低公式执行风险；应保持所有用户值为字符串并回归测试公式样式内容。
5. **前端可用性**：已有响应式断点和原生对话框；CSS 使用远程 Google Fonts，离线可能回退且会产生第三方请求。动态数据全量重绘，没有长列表/焦点/减少动态效果专项验证。
6. **删除不可撤销**：已有确认框，删除后无撤销；明确告知用户。
7. **打包编码**：ZIP 的博客文件名按 GBK 编码，需要正确读取。文件本身已保留为 `博客草稿.md`。

## 设计决策（编码前）

沿用现有 Python + 原生 DOM 架构，不迁移 React，也不引入组件/动效依赖。保留「人间有信」和原有功能层级，按交接材料采用暖纸、深墨绿、鼠尾草、珊瑚星标；优先优化列表、表单和响应式状态。动画只用 CSS transform/opacity，`prefers-reduced-motion` 下取消连续背景与非必要位移。联系方式增行为独立可编辑的标记行，保存为向后兼容的 `methods` 数组，并继续兼容现有 `phones` / `emails` / `address` 字段。
