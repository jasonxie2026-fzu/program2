# 独立展示页实施说明与验收（不要替换原通讯录）

## 为什么需要独立页面

此前用户明确增加了“给项目一个设计感强的作品展示页”的需求。它面向老师查看作品和访客认识项目，但收藏、Excel 等作业评分必须由主应用真实功能支撑。

## 推荐路由

- **优先**：`/showcase`，主应用保持原有 `/` 或它目前的真实路由。
- 如果当前静态托管或原框架不支持历史路由直达：使用 `/showcase.html` 或对应静态路径，**必须在部署环境直接刷新测试**。不要盲目加入 History API 路由导致线上 404。
- 在主应用导航中加一个低调的“作品介绍/项目展示”入口；展示页的顶部和底部都有真实“进入通讯录” CTA。

## 原型文件

`showcase-reference/index.html`：原生、无第三方资源依赖的完整单文件演示。
`showcase-reference/preview-desktop.png`、`preview-mobile.png`：浏览器实际渲染的全页截图；`preview-hero.png`：桌面首屏。

### 目标页面结构

1. 顶部品牌导航和“进入通讯录”。
2. 情绪化首屏、暖纸张背景、编辑式中文大标题，右侧示例联系人卡片（可切星标、详情抽屉）。
3. 三种重要能力 Bento 功能卡：星标、多个联系方式、Excel 自由备份。
4. 滚动三步叙事、书信引文、结尾 CTA。
5. 响应式、可读、键盘可操作、减少动效。

### 数据隔离

- `showcase` 内三个示例联系人**是假的**，不得保存到真实联系人数据模型、localStorage/IndexedDB/API，也不能访问真实个人联系人。
- 详情内示例电话和邮箱必须显然只是示例；该页不应该有“真的成功导入了 Excel”的假流程。
- 可以用纯 JS 的局部演示状态或组件内 state，刷新后还原初始示例即可。
- 展示页不引入广告、付费、假数据增长 KPI、无关的注册登录。

### 动效与技术集成

- 如果项目是 React，可把原型拆成 ShowcaseHero、DemoAddressBook、FeatureBento、NarrativeSteps、ClosingCTA 等小组件；样式隔离避免影响主应用。
- 如果项目是原生 JS/其他框架，优先保留原生实现，不为展示页迁移整个项目。
- 保留轻微标题入场、窗口/纸张缓慢浮动、卡片轻抬和示例心形反馈；在 hover/focus 时暂停不断漂浮的卡片，使交互稳定。
- `prefers-reduced-motion` 静止降级；离屏详情面板隐藏时不能扩宽移动 viewport；使用语义按钮、`aria-pressed` 和关闭后的焦点恢复。

## 验收标准

- 直接访问 /showcase（或等价路径）成功；从主应用可进入展示页；两个「进入通讯录」CTA 都回到真实功能区。
- 示例收藏从 1 条变 2 条并切换星标筛选时显示 2 条；详情开/关及 Esc 正常；示例收藏不影响原通讯录任何数据。
- 375、390、768、1440px 没有水平滚动/文本截断，按钮可点击；减少动效模式仍完整可用。
- 主应用 CRUD / 收藏 / Excel 导入导出与原来一致且有可重复的测试证据。
- 展示效果与原型明显一致，但可根据真实框架及性能裁剪细节。
