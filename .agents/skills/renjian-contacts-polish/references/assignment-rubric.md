## 作业过程清单

- Fork 课程所给仓库（若已知），提前模块划分，团队沟通 Git 协作与编码规范。
- GitHub 仓库 **至少 3 次提交**，截止前上传可构建代码和相关文档。
- Release 一个版本并发起 Pull Request（帖子 checklist 中明确要求）。
- 截止前发布并提交个人 Markdown 博客；博客发布后可能需审核，不能压线。
- 文章开头须有课程说明表：课程 `Software Engineering (FZU–MU)`、Team Name、Assignment Requirements、Objectives、Other References。
- 博客包含：项目 GitHub 地址与访问链接（若有）、GitHub 提交历史截图与成员提交数、功能实现思路、运行截图、**完整运行视频**、分工/贡献比例合计 100%（组队时）、协作困难与解决办法（组队时）、**每人一张 PSP 表**。
- 同组可共同准备 Markdown 内容，但 **每位学生各自提交博客**。

## 项目优先级

P0（不能因 UI 迭代受损）：功能 60 分 + 本地持久化 + Excel 无损往返。
P1（直接得分）：页面风格 10 分 + 演示友好的截图/视频/说明 30 分。
P2（非必需）：云部署 +15，须核实云服务器要求与真实访问性。

## 证据要求

勿把“计划通过”写成“已通过”；Git 提交、PR、Release、云部署和博客必须由仓库或平台真实记录证明。课程要求来源只以上面原始帖子为准；如果老师另有最新补充，以更新后的老师要求覆盖本备忘。
