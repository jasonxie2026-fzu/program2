# 多联系方式数据模型与 Excel 合约（实现指引）

不要假定当前代码使用以下字段；这是给 Codex 对齐现有模型时的**建议结构**。先审计已有持久化数据和 Excel 模板，提供无损迁移而不是重置。

## 建议的规范化联系人模型

```ts
type Contact = {
  id: string;                 // stable id; never use array index as key
  name: string;
  company?: string;
  notes?: string;
  favorite: boolean;
  methods: Array<{
    id: string;
    type: 'phone' | 'email' | 'social' | 'address' | 'other';
    label?: string;          // 手机、工作、微信、家庭等
    value: string;
  }>;
  createdAt?: string;
  updatedAt?: string;
};
```

电话必须保留 `+`、前导零与分隔符；按**文本**处理，不能转换 Number。邮箱和社交账号不要强制数字格式。星标应与联系人 id 绑定，而非名字字符串；删除/修改联系人不应误改其他人。

## Excel 格式要求（来自老师）

- 导出 `.xlsx`：**每个联系人仅占一行；每种信息单独放在相应列**。
- 推荐固定基础列：`Name`, `Favorite`, `Company`, `Notes`；联系方式动态扩展：`Phone 1`, `Phone 1 Label`, `Phone 2`, `Phone 2 Label`, `Email 1`, `Email 1 Label`, `Social 1`, `Address 1` 等。总列宽由导出批次每种方式的最大数量决定，不得静默截断第 2/3 个号码。
- 不应仅使用一个 `methods JSON` 单元格代替联系方式分列；可以附加 `Contact ID` 或 `Methods JSON` 辅助列供完整回放，但**必须仍有单独人类可读信息列**。
- 导出的每个字段必须按字符串处理，不得引入会被表格软件执行的公式注入。通过库正确创建字符串单元格（`t:'s'`）；导入时校验单元格类型、不得执行任意脚本。
- 导入同一份 Excel 后保留多联系方式、标签、公司/备注、星标；空单元格不得覆盖已有有效数据（合并策略须明确）。
- 提供下载的**空白模板**及用户可读表头说明，确保与导入解析器一致，特别是中文/英文表头映射规则。
- 不破坏旧模板兼容：旧版 `Phone`/`Email` 等列映射到第一联系方式，新字段默认为缺失；提供迁移测试。

## 导入 UX 与数据安全

1. 文件选择/拖拽后做扩展名、MIME、大小限制（合理上限，如 5–10MB）及表头校验；错误必须说明原因，不能只显示“失败”。
2. 解析时显示总行数、将添加/跳过/冲突的数量和至少前几行预览。
3. 冲突策略明确：支持“跳过重复”或“合并/覆盖（需确认）”；不能悄悄产生完全重复或覆盖用户联系人。
4. 任何失败都不能清空现有通讯录；尽量先在内存里完成验证、汇总，再一次性写入持久化；若执行部分导入，要说明已完成的条数。
5. 支持零行导出仍生成合法模板或给出明确的空模板下载行为。
6. 测试：一位联系人 2 电话、2 邮箱、1 微信、1 地址、favorite=true；导出->清空测试数据->导入->逐字段对比。再测中文、国际电话、空字段、坏文件、重复行、100+ 数据、刷新后保存。
7. 由于应用公开说明数据保存在当前浏览器，设计保留明确备份提醒与“导出 Excel 备份”入口，不向外部服务上传真实联系人。
